# Build system modernization (autoconf 2.72, Makefiles)

Status: **decision list, awaiting answers** (2026-10-20). Nothing implemented yet.

Trigger: a `make` on prod (autoconf 2.72) regenerated `configure` and printed a wall of
obsolete-macro warnings. `configure.in` is written for autoconf 2.69 (the committed
`configure` was generated by 2.69 in 2023, commit 08a0954). The warnings are harmless
today; the user wants them gone and the build system cleaned up while at it.

Survey: Explore agent, 2026-10-20, over `upstream/master` @ b3231be. The fork
(`ircv3.2-upgrade`) carries a `configure.in` ~350 lines larger (rocksdb, zstd, libgit2,
keycloak options, each with the same includes/libs prefix trio) and a much larger
`ircd/test/Makefile.in`; the same transformations apply there afterwards.

## Decisions

### A. Autoconf 2.72 modernization — no behaviour change (required)

- Rename to `configure.ac`; `AC_PREREQ([2.72])` first; two-argument `AC_INIT` with
  `AC_CONFIG_SRCDIR`; `AC_CONFIG_HEADERS`; `AC_CONFIG_FILES` + bare `AC_OUTPUT`;
  `AC_CONFIG_COMMANDS` for the summary (today it is registered after output and never prints).
- `AC_TRY_COMPILE` / `AC_TRY_RUN` → `AC_COMPILE_IFELSE` / `AC_RUN_IFELSE` with cross-compile
  branches; two-argument `AC_CHECK_TYPE` → `AC_TYPE_INT16_T` family; `AC_PROG_LEX([noyywrap])`
  (the lexer defines its own `yywrap`, `ircd/ircd_lexer.l:361`).
- Drop `AM_PROG_CC_STDC`, `AC_PROG_CC_C99`, `AC_HEADER_STDC`, `AC_HEADER_TIME`, `AC_STRUCT_TM`
  (their symbols have zero references in `ircd/` and `include/`).
- Literal `AC_CHECK_HEADER` with the prefix on `CPPFLAGS` (fixes `-I` landing in `CFLAGS`
  and the `HAVE__…` defines that are silently dropped today); `AS_HELP_STRING` everywhere;
  `test … -o …` → `||`.
- Delete `aclocal.m4` (only carries the automake shim and `m4_include`); custom macros into
  `m4/`; refresh `config.guess`, `config.sub` (2005: no aarch64/riscv64) and `install-sh`
  (X11R5); regenerate `configure` and `config.h.in` with 2.72 and commit them.
- `AC_SYS_RESTARTABLE_SYSCALLS` (obsolete, no replacement): its define switches on
  `siginterrupt(SIGALRM, 1)` at `ircd/ircd_signal.c:277`. **Define it unconditionally**: every
  supported host qualifies, so the binary is identical.

### B. Dead code removal — low risk, confirmation requested

- `--with-{openssl,geoip,mmdb}-includes/-libs` produce `SSL_*_PATH` / `GEOIP_*_PATH` /
  `MMDB_*_PATH` defines with zero references. Keep the options, drop the defines.
- `unet_SIGNALS` (`acinclude.m4:74`): POSIX_SIGNALS / BSD_RELIABLE_SIGNALS /
  SYSV_UNRELIABLE_SIGNALS have zero references.
- `--with-leak-detect`: needs a patched gc 6.0 (`ircd/memdebug.c:15`), prints the wrong
  variable (`configure.in:251`). Remove.
- `PATH_DEVNULL`, `SIZEOF_SHORT`, `SIZEOF_INT64_T`, unused `HAVE_*` header defines,
  `stamp-h.in`, the `acconfig.h` rule, the `tools/transition` and `cvs update` targets,
  dead Makefile variables (`DEFS`, `MPATH`, `RPATH`, `TOUCH`, `AWK`, `PURIFY`, `RINGLOG_O`),
  the commented-out rules at `ircd/Makefile.in:378-394`.
- **Behaviour trap:** `unet_NONBLOCKING` (`acinclude.m4:7`) uses `$ac_cv_type_signal`
  (never set) and test programs that no longer compile under GCC 14 (implicit int, implicit
  `exit`), so every current build silently falls back to `NBLOCK_SYSV` = `ioctl(FIONBIO)`
  (`ircd/os_generic.c:327`). A working probe selects `fcntl(O_NONBLOCK)`. Both are correct
  on Linux; fix the probe and say so in the PR.

### C. Improvements

- `pkg-config` first (`PKG_CHECK_MODULES`) for openssl and libmaxminddb — on the fork also
  rocksdb, zstd, jansson, curl, libgit2, cmocka — with the prefix options as the fallback.
  Removes the hard-coded `/usr/local` default (why `USE_GEOIP` is off in every local build)
  and the `-Wl,-rpath=/usr/lib` appended today (`configure.in:754`).
- Dependencies via `-MMD` at build time instead of the stale committed block
  (`ircd/Makefile.in:396-1362`: lists `m_tmpl.o`, `table_gen.o`, lacks `lex.yy.o`,
  `y.tab.o`, `version.o`) and a `depend` target that rewrites the tracked `Makefile.in`.
- `version.c` regenerated only when the git describe / source list changes, not
  `.PHONY` (today every `make` relinks the daemon).
- `make check` builds and runs the unit tests; `ircd/test/Makefile.in` honours the
  configured `CFLAGS`/`CPPFLAGS`/`LDFLAGS` instead of hard-coding `-g -Wall`.
- `DESTDIR`; `mkdir -p`; a working `uninstall` (today it globs `ircd.9*`, never matching
  `ircd.2…`); `y.tab.c y.tab.h &:` grouped rule for `-j`; `CPPFLAGS` before `CFLAGS` so
  `-I${top_srcdir}/include` wins over library `-I`; `all:` not calling a literal `make`.
- Drop the mtime-driven self-regeneration rules (`Makefile.in:117-121`) so a checkout can
  never run the box's autoconf again (the prod symptom).
- Top-level subdirectory loop fixed (`ircd/test` handled, errors not ignored; `uninstall`
  and `maintainer-clean` exist in every subdir Makefile).
- Out-of-tree builds: `patchlist.h`, `git describe` / `.release` lookups and `depend` run in
  the build-dir cwd; make them srcdir-aware or document in-tree only.

### D. User's call — left alone otherwise
