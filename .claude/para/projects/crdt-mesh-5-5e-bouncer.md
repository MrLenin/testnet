## Why not the pure tunnel
The CR 'B' tunnel re-injects BS C with `sptr=FindNServer(origin)` to PRESERVE the per-hop-relay
election — i.e. it spends its hardest effort keeping the bug's own mechanism correct over a new
transport, leaves two convergence models in the tree forever, and at MR-6 (every node overlay-only)
becomes a liability. Doc-native reuses the PROVEN substrate (LWW/OR-Set/min-register/beacon-lease +
shadow→authoritative phasing) that already converges 8 nodes at 0-mismatch.

## DECISIONS (RESOLVED by the user 2026-06-22)
1. **Accept the brief heal overlap — the binding constraint is GHOST-FREEDOM, not "no QUIT" (user correction 2026-06-22).** "No visible QUIT" is WRONG as an absolute: if a client ever saw the loser as a distinct entity (channel member, or MONITOR/WATCH target), removing it WITHOUT a QUIT leaves a permanent ghost on that client — the exact failure we're avoiding. A QUIT there is MANDATORY, not a defect. So the goal is **minimize who ever sees the duplicate-as-distinct + emit a clean standard QUIT to anyone who did**, NOT suppress teardown.
   - **Common case (single revive): no duplicate.** A new connection lands on ONE node; all other nodes materialize the one canonical identity from the doc. One visible identity, nothing to tear down. The overwhelming majority.
   - **Symmetric-split-both-revive (rare edge):** two nodes each revived the account during a mesh partition → two genuinely-distinct visible faces. On heal the loser is torn down with a NORMAL QUIT *for the observers that saw it* (ghost-free, correct) — **reuse the existing collision/kill-cascade + burst machinery; do NOT build QUIT-suppression (that creates ghosts).** Matches invariant #6's deliberate visible-teardown-over-ghost choice. Same-nick dual-revive = a nick collision resolved by the standard resolver; loser-side channel observers see QUIT + the winner's burst-join (unavoidable — IRC has no member-numeric-rewrite).
   - **What we DO minimize:** the WINDOW the duplicate is visible (revive-as-alias-early so a 2nd connection stays an invisible alias when possible) and **the winner side sees nothing** (it only ever saw the winner).
   - **MONITOR/WATCH (nick-based, separate layer):** offline fires iff the nick truly has NO remaining connection. The only correct suppression = "don't report offline while the same nick is still present via the winner"; order winner-presence-before-loser-teardown to shrink the loser-side transient; accept a brief same-nick flap in the rare dual-revive.
   **Validation cases (M5/M6): (i) WINNER-side observers see NOTHING on heal; (ii) LOSER-side observers that saw the loser get a clean QUIT (NO ghost — assert the user is gone from their member list); (iii) MONITOR/WATCH on the account nick sees NO offline while the nick remains present via the winner.**
2. **Single-gateway** for the bouncer cutover (consistent with MR-4d/Tier C). Multi-gateway rides later.
3. **Keep `(account,sessid)` opaque keys through M7; land profile-union separately** (don't couple two large changes).
4. **Start cycle-bounded** heal resolution; turn on eager multi-hop relay (`c04581d`) for bouncer frames only if the heal window bites in testing.
